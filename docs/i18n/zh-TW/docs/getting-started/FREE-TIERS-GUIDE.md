> **TL;DR** ：帶上您自己的合格提供者帳戶。 OmniRoute結合了你配置的連結；它不會發布廣告中的總代幣預算。免費存取可能需要註冊、 API密鑰、批准或付款方式。提供者限制、隱私權政策和條款仍然適用。

## 什麼是免費套餐？

許多AI提供者提供某種形式的**免費訪問**。根據提供者的不同，這可能意味著無身份驗證端點、定期配額、速率限制的無上限存取、註冊授權、手動批准或臨時促銷。某些選項需要帳戶、 API金鑰、信用卡、 KYC或接受特定於提供者的條款。

OmniRoute**聚集體**配置連接到一個端點。您仍然需要單獨註冊每個需要帳戶的提供者。連接這些帳戶並使用`model: "auto"`在符合條件的目標之間進行路由。全新安裝不能有符合條件的免鑰匙目標；單獨安裝OmniRoute並不能保證聊天回應成功。

## 如何疊加免費層級

OmniRoute的神奇之處在於**堆疊免費層**。您無需依賴一個提供者，而是連接多個免費提供者，並讓OmniRoute自動為每個請求選擇最佳提供者。

### 範例：更廣泛的免費套餐覆蓋範圍

連接多個提供者以減少對任何單一配額的依賴：

1. **Gemini** —定期 API 金鑰配額
2. **Groq** —定期 API 金鑰配額
3. **授粉**—無鑰匙、限速訪問
4. **LongCat** —一次性註冊補助（需要KYC）

然後使用`model: "auto"`和OmniRoute將：

- 首先嘗試排名最高的合格連接
- 如果其配額或運行狀況檢查失敗→嘗試下一個配置的提供程序
- 如果無密鑰提供者不可用→繼續完成其餘目標
- 如果沒有符合條件的連線成功→回傳錯誤；註冊積分僅在有效且可用時可用

**結果**：具有自動回退—更廣泛的免費套餐覆蓋範圍並不能保證無限容量。

## 如何連接免費提供者

### 第 1 步：開啟儀表板

在瀏覽器中轉到`http://localhost:20128` 。

### 第 2 步：前往提供者處

點選**提供者**在側邊欄中。

### 第 3 步：按一下“新增提供者”

點選**+新增提供者**按鈕。

### 第 4 步：選擇免費提供者

瀏覽目錄並檢查每個提供者目前的`hasFree`、身份驗證、配額、隱私和ToS元資料。提供者卡和[免費套餐參考](../reference/FREE_TIERS.md)區分了經常性池、 uncapped/keyless訪問、註冊積分、已停止的條目和高風險來源。

### 步驟5：點擊連接

對於`NOAUTH`提供者， OmniRoute不請求上游憑證。這並不保證上游接受第三方客戶端或具有可用容量。 OAuth和 API 金鑰提供者必須透過其記錄的帳戶流進行連線。您的客戶端仍然使用OmniRoute API鑰，如圖所示**儀表板→端點**啟用路由器身份驗證時。

### 第 6 步：重複

連接多個條款和隱私模型適合您的用例的提供者。

## 來自 dsh“我們的免費模型”

dsh 代理主機的[dsh-our-free-model](https://github.com/Ebony-Vinyl/dsh-our-free-model)插件到達兩個上游。 OmniRoute已經為每個提供者都有一個提供者，但其中只有一個是OmniRoute中的免費路徑：

| 插件通道 | 上游                                    | OmniRoute提供者             | OmniRoute免費嗎？ | 如何連接                                                                 |
| -------- | --------------------------------------- | --------------------------- | ----------------- | ------------------------------------------------------------------------ |
| 千通道   | Kilo AI網關 (`api.kilo.ai/api/gateway`) | `kilo-gateway` （別名`kg`） | 是的              | API key 可選：將其留空以使用網關的空閒池                                 |
| 自由車道 | OpenCode禪 (`opencode.ai`)              | `opencode-zen`              | 不                | 來自[opencode.ai/zen](https://opencode.ai/zen)的您自己的OpenCode API密鑰 |

**公斤。**將空閒池稱為`kilo-gateway/<model>`或`kg/<model>`，例如`kg/kilo-auto/free` （Kilo 的免費自動路由器）或網關的`:free`模型之一。自由組旋轉； `kilo-gateway`傳遞不在OmniRoute內建清單中的模型 ID，因此可以在目錄包含模型之前呼叫網關今天列出的模型。 Kilo 的免費模型卡表示，上游提供者可能會記錄提示並用於改善其服務，因此不要發送敏感資料。

**OpenCode.**該插件的免費通道是OpenCode的免密鑰優惠。 OmniRoute不提供此優惠作為免費存取：

- 應OpenCode運營商的請求，刪除了OmniRoute的無密鑰OpenCode提供者（請參閱[刪除的提供者](../reference/REMOVED_PROVIDERS.md)）。
- OpenCode的[端點文件](https://opencode.ai/v2/docs/console/models/#endpoints)將其免費聊天優惠與OpenCode自己的客戶端連結起來，因此OmniRoute不會將其視為免費或將其標記為免費。

插件顯示的模型 ID，例如`deepseek-v4.1-flash-free`、 `mimo-v2.6-flash-free`和`nemotron-3.5-lightning-free`，位於`opencode-zen`目錄中。將`opencode-zen`與您自己的OpenCode金鑰連接，以便根據您的OpenCode帳戶條款使用它們。

**插件的本地端口。**該插件可以在本地 OpenAI 相容連接埠（預設`18899`）上公開其模型。任何此類端點都可以添加為[自訂 OpenAI 相容提供程序](../guides/USER_GUIDE.md#custom-openai-compatible-providers)，但OmniRoute不會安裝、啟動或更新插件，並且插件決定哪個上游服務於每個請求。無論哪個客戶端發送請求，上述OpenCode限制都適用於OpenCode的報價。

## 正確閱讀目錄

- `NOAUTH`表示OmniRoute不會要求您提供提供者憑證；它不保證正常運作時間、隱私或無限容量。
- `hasFree`是發現元資料。它可以代表定期配額、無鑰匙訪問、註冊積分、批准計劃或促銷。
- `recurring-uncapped`表示沒有公開的代幣上限；速率和並發限制仍然適用。
- 註冊授權用完後，`one-time-initial`不會重複出現。
- 預設情況下，`tos: avoid`提供者被排除在自動路由之外 (`excludeTosAvoid`)。連線帳戶不會繞過此過濾器。任何運營商覆蓋都應遵循對提供者條款和帳戶風險的審查。
- 標記為`discontinued`條目仍然是歷史證據，不得以當前免費的方式呈現。

## OmniRoute如何讓免費套餐變得更好

### 1. 自動回退

如果一個免費提供者繁忙或當機， OmniRoute會自動嘗試下一個。你不需要做任何事。

### 2. 智慧路由

OmniRoute選擇了**最佳免費提供者**對於每個請求，基於：

- 速度—現在哪個提供者速度最快？
- 品質—哪個提供者最適合這項任務？
- 容量—哪一家提供者還有剩餘配額？

### 3. 代幣節省

OmniRoute的壓縮管道可以減少合格的提示和工具輸出令牌。實際節省取決於內容、所選引擎、提供者會計和保真度設定；壓縮不會將每個提供者配額乘以固定數量。

### 4. 多帳戶支持

如果提供者條款允許多個帳戶或憑證， OmniRoute可以將每個連線視為單獨的路由候選者。不要建立額外的帳戶來逃避提供者的配額或存取策略。

## 常見問題

### “這真的是免費的嗎？”

該目錄記錄了提供者發布的術語和項目研究，但報價可能會發生變化。使用前驗證提供者的當前定價、配額、隱私權政策和資格。

### “免費套餐會用完嗎？”

每個提供者都可以限制速率、更改模型、暫停存取或離線。多個連線可以改善後備覆蓋範圍，但不能保證可用的免費路由。

### “我可以使用免費提供者進行生產嗎？”

僅當提供者的SLA、資料處理、限制和條款滿足您的生產要求。關鍵工作負載應該受到監控、符合合約規定的後備措施。

### “有什麼問題嗎？”

權衡可能包括嚴格的限制、候補名單、 KYC、信用卡驗證、提示培訓、較弱的隱私、無SLA、模型流失、地理限制、超額付費或帳戶政策風險。 OmniRoute顯示可用的元資料；您選擇要啟用的內容。

### “如何獲得更多免費額度？”

1. 連接更多免費提供者
2. 啟用適當的壓縮引擎並衡量您的工作負載節省情況
3. 使用`auto/cheap`確定free/cheap提供者的優先級
4. 在不違反提供者條款的情況下新增其他允許的提供者或憑證

### “免費提供者的品質是否較差？”

未必。一些提供者透過付費途徑提供相同的模型系列，但限制、延遲、隱私、可靠性和模型版本可能有所不同。使用免費提供者排名頁面作為品質訊號並驗證所提供的實際模型。
